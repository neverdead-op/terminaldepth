# Terminal Depth — инструкции для Codex

## Проект и общение
- 3D top-down action с добычей, крафтом и прокачкой. Godot 4.x, GDScript; `project.godot` указывает 4.7 / Forward+, Windows D3D12, Jolt. Точную установленную версию проверять при необходимости.
- Общаться по-русски, просто и кратко: автор без опыта программирования. После правок сообщать результат и способ проверки (сцена/кнопки). Не создавать длинные отчёты без запроса.

## Работа с контекстом и изменениями
1. Перед изменением кода прочитать соответствующий раздел [PROJECT_MAP.md](PROJECT_MAP.md), затем только относящиеся к задаче файлы и необходимые зависимости.
2. Начинать с имён файлов, объявлений и целевого поиска `rg`; полные файлы читать по необходимости. Не выполнять полный аудит при каждом запросе. Карта — указатель, а не запрет дополнительного исследования.
3. Предпочитать небольшие проверяемые изменения. Не переписывать рабочие системы без технической необходимости и не создавать дубли существующих механизмов.
4. Не менять баланс, визуальный стиль и механику без задания. Не выполнять дополнительные улучшения вне задачи.
5. Сохранять совместимость игровых систем, публичных методов, сигналов, путей узлов, групп и форматов сохранения. До изменения контракта проверять его потребителей.
6. Не удалять ассеты, исходники, старые библиотеки и функциональность без прямого указания. Не откатывать чужие изменения; перед работой проверять состояние рабочей папки.
7. После существенного изменения архитектуры обновлять `PROJECT_MAP.md`; подробности конкретной подсистемы держать в соответствующем `docs/`, а не наращивать здесь журнал сессий.

## Godot, сцены и ресурсы
- Комментарии и пояснения `##` — по-русски; имена кода — по-английски. Настраиваемые параметры выносить в `@export`, где это уместно.
- Ввод добавлять через `scripts/input_setup.gd`, с клавиатурой и геймпадом; использовать физические клавиши для русской раскладки.
- Сохранять существующие имена/пути узлов, UID и ссылки ресурсов. Общие материалы/ресурсы не менять глобально ради одного экземпляра; учитывать наследование сцен и `@tool` в редакторе.
- `scenes/hub.tscn` содержит ручную расстановку: не пересобирать и не заменять генератором. Перемещать `Geometry/Prop…` целиком вместе с `Shape`, а не только его дочернюю геометрию. Таверна наследует эту базу.
- Сборщики могут перезаписать сцены/библиотеки. Запускать только по задаче, заранее проверив выходные пути; художественные тесты не подменяют кампанию.
- Слои: 1 — мир, 2 — игрок, 3 (маска 4) — враги, 5 (маска 16) — двери. При правках попаданий/навигации сверять реальные маски. Сохранять контракт `take_damage(amount, element, source)` и корректный первый отрезок пули от стрелка.

## Действующие авторские ограничения
- Текущий этап анимаций — двуручный автомат и пистолетный хват. Лук отложен: без отдельного запроса не пересобирать и не настраивать его анимации.
- Направление — викторианская готика. Старые sci-fi имена/ассеты сохранены ради совместимости; не переделывать весь ассортимент и следующие зоны автоматически.
- Герой — красная охотница, одобренный скелет 68 костей. Физика ткани отложена: не возвращать; хвосты шарфа удалены, воротник оставлен. Эксперимент отдельно в `art_source/red_huntress_cloth_experiment` с `.gdignore`. См. `docs/HUNTRESS_PLAYER.md`.
- Текущий лук использует новые FBX: Draw Arrow → Overdraw → Recoil, вылет на третьем кадре Recoil. После общей `bake_archery.gd` требуется `bake_bow_combat.gd`; прежний `bake_bow_action.gd` не запускать. Не возвращать статичное удержание рук IK. См. `docs/ARCHERY_PROTOTYPE.md`.
- `level1_playtest` — отдельный тест: 64 врага (3 тяжёлых), автомат с fire+ricochet, собственная камера. F8/«Камера» ставит бой на паузу; настройки переживают F7 до выхода. Начало/сброс: 10.5 м, 52°, FOV60. У игрока Run/Sprint ×0.85; прежнее ускорение ×1.25 в тесте убрано. Прежние 8.5 м, 12.5 м и 10 м/FOV52 — история.
- Исследование исходной текстуры карты отложено. `use_source_textures=false`, матовый макет активен; дефект атласа не доказан, UV не объявлять исправленными. См. `docs/LEVEL1_SUPPLIED_PLAYTEST.md`.
- Для деревни сохранять одобренный пол `assets/textures/victorian_garden/stylized_v2/flagstones_red_petals_albedo.png`, без широких разломов; стеновые текстуры — стилизованные v2. Свет — холодная глубина, локальный тёплый, читаемый герой; cel shading не включать без задания.
- Сохранять принятые готические UI и `UiIcons.draw_item_picture`; навыки/модули имеют существующие правила. См. `docs/UI_GOTHIC_V2.md`.

## Проверка и сохранения
- Godot не установлен: консольная версия для запусков без окна — `C:\Users\user\Desktop\Godot_v4.7.2-stable_win64_console.exe`. Быстрая проверка разбора: `--headless --editor --quit --path .` (обновляет кэш `.godot/` — это нормально, сам кэш не править).
- После правок выполнять доступные релевантные проверки из карты; проверять соответствующий тест перед запуском. Для документации достаточно проверки ссылок/диффа.
- Временные тесты — в `ztest/` (там уже лежат чужие диагностики и изолированный профиль `ztest/profile`; удалять только созданное собой). Проект под локальным git: после законченной и проверенной правки — коммит с русским описанием; чужие незакоммиченные изменения в него не включать.
- `CLAUDE.md` — короткая памятка для Claude со ссылками сюда; старая sci-fi версия — только в истории git.
- Не проводить потенциально разрушительные операции с реальными сохранениями. `Game.testing` блокирует `Game.save()`, но прямые вызовы `SaveGame.write/delete` обходят эту защиту. Не запускать обычную «Новую игру» ради теста; проверять также запись настроек и ресурсов.
- Для визуальных изменений нужна проверка реального кадра; headless не подтверждает внешний вид, FPS или корректное завершение D3D12.
- Стабильный FPS и прежняя проблема завершения D3D12 не подтверждены как исправленные. У старого полного `test_onboarding` известны устаревшие ожидания заданий; проверку популяции запускать отдельно (`-- --population-only`).
